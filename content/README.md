# content: генерация карточек NGSL

Пайплайн, который заполняет `data/words.json` карточками для знаменательных слов NGSL 1.2. Сам контент пишут субагенты Claude Code. Скрипты нарезают для них работу, проверяют ответы правилами из `data/README.md` и собирают результат.

Веб-приложение этот проект не использует: оно читает только готовый `data/words.json`.

## Установка

Нужен [uv](https://docs.astral.sh/uv/); Python 3.11 он поставит сам.

```bash
cd content && uv sync
```

Все команды пайплайна запускаются из корня репозитория:

```bash
uv run --project content content <шаг> [аргументы]
```

Каталог данных по умолчанию — `data/` в корне репозитория. Другой каталог задаётся флагом `--data DIR` перед шагом.

## Пайплайн

```
NGSL_12_stats.csv
   │ 1 classify-batches        скрипт
   ▼
gen/classify/NNN.in.json  ──2──► субагенты Sonnet (prompts/classify.md) ──► NNN.out.json
   │ 3 merge-pos               скрипт → gen/pos.json, gen/dropped.md (просматривает человек)
   ▼
   │ 4 card-batches            скрипт: уровни, формы-леммы, пачки по 20
   ▼
gen/cards/NNN.in.json     ──5──► субагенты card-writer (prompts/card.md) ──► NNN.json
   │ 6 validate                скрипт → gen/report.json; невалидное снова уходит в шаг 4
   ▼
   │ 7 assemble                скрипт → data/words.json
```

| Шаг | Команда | Что делает |
|---|---|---|
| 1 | `classify-batches` | Режет CSV на пачки по 200 лемм. Отказывается работать, если пачки уже есть. |
| 2 | субагенты | Для каждой леммы определяют основную часть речи или `null` для отбрасываемых слов (сегменты перечислены в `prompts/classify.md`). Помечают сомнительные случаи. |
| 3 | `merge-pos [--force]` | Проверяет ответы: каждая лемма ровно один раз, поля корректны. Пишет `pos.json` и `dropped.md`. Без `--force` не перезаписывает `pos.json`, потому что в нём могут быть ручные правки. Леммам из первых 30 по частотности ставит `null`, что бы ни ответил субагент. |
| 4 | `card-batches [--pilot \| --ids a,b] [--limit N]` | Пишет следующие пачки карточек. Подробности ниже. |
| 5 | субагенты | Пишут карточки в черновик `NNN.draft.json`, проверяют его через `validate --file` и переименовывают в `NNN.json`. |
| 6 | `validate [--file F]` | Без `--file` проверяет последнюю версию каждой карточки и пишет `report.json`. С `--file` проверяет один ответ субагента. Код выхода 1, если есть ошибки. |
| 7 | `assemble` | Собирает валидные карточки в `data/words.json` (порядок `freqRank`, ключи как в `data/README.md`, отступ табами). Падает и оставляет старый файл, если на какую-то часть речи приходится меньше 3 слов. |

### Словарь и уровни

В словарь входят леммы, у которых в `pos.json` указана часть речи (`noun`, `verb`, `adjective`, `adverb`, `preposition`, `conjunction`, `pronoun`). Уровни не генерируются. Слова словаря в порядке частотности делятся на 6 равных групп A1…C2: `LEVELS[i * 6 // n]`.

### Пачки карточек (шаг 4)

- **Без аргументов** берёт слова без валидной последней версии карточки, по частотности.
  - Слова из ожидающих пачек пропускаются. Ожидающая пачка — та, у которой есть `NNN.in.json`, но нет `NNN.json`.
  - Невалидная карточка возвращается в новую пачку вместе со списком ошибок (`errors`) и прошлой версией (`previous`).
  - Слово, у которого 3 последние версии подряд невалидны, не берётся и попадает в `gen/stuck.md`.
- **`--pilot`** берёт 25 слов, равномерно разбросанных по частотному списку, даже если их карточки уже валидны.
- **`--ids a,b`** берёт указанные слова, тоже даже валидные.
- **`--limit N`** ограничивает число новых пачек. Работает только без `--pilot` и `--ids`.

Каждый элемент пачки:

```json
{ "word": "find", "pos": "verb", "level": "A1", "freqRank": 81, "lemmaForms": ["found"] }
```

`lemmaForms` — леммы словаря, похожие на формы этого слова. Их нельзя ставить в пропуск Cloze, потому что это другие слова словаря.

### Версии и попытки

Отдельного файла состояния нет, всё выводится из файлов в `data/gen/cards/`.

- Пачки нумеруются одной сквозной последовательностью, первичные и перегенерация вперемешку.
- Актуальная версия карточки берётся из ответа с наибольшим номером, в котором она есть.
- Учитываются только id, которые пачка запрашивала в своём `NNN.in.json`. Лишние ключи в ответе игнорируются, а `validate --file` о них сообщает.

## Файлы в `data/gen/`

Каталог в `.gitignore`. Это рабочее состояние пайплайна, по нему прогон продолжается в любой сессии.

| Файл | Кто пишет | Что это |
|---|---|---|
| `classify/NNN.in.json`, `NNN.out.json` | шаг 1 / субагенты | пачки классификации и ответы |
| `pos.json` | шаг 3, правки руками | `{lemma: pos \| null}` для всех лемм NGSL |
| `dropped.md` | шаг 3 | сначала сомнительные, потом отброшенные, с причинами |
| `cards/NNN.in.json`, `NNN.draft.json`, `NNN.json` | шаг 4 / субагенты | пачки карточек, черновики и ответы |
| `report.json` | шаг 6 | ошибки по id, только невалидные |
| `stuck.md` | шаг 4 | слова после 3 неудачных попыток подряд |

## Как провести прогон

Субагентов запускает основная сессия Claude Code.

### 1. Классификация

```bash
uv run --project content content classify-batches     # 15 пачек
```

На каждую пачку запустить субагента на Sonnet, по 4 параллельно:

```
Read content/prompts/classify.md and follow it.
Input: data/gen/classify/NNN.in.json
Output: data/gen/classify/NNN.out.json
```

```bash
uv run --project content content merge-pos
```

Если `merge-pos` сообщает об ошибках, перезапустить субагента на названной пачке. После этого просмотреть `data/gen/dropped.md` и внести правки прямо в `data/gen/pos.json`.

### 2. Пилот

```bash
uv run --project content content card-batches --pilot
```

Запустить субагента `card-writer` (`.claude/agents/card-writer.md`: Opus с effort low, только Read, Write и Bash, поэтому своих агентов он не запускает):

```
Input: data/gen/cards/NNN.in.json
Output: data/gen/cards/NNN.json
```

Прочитать `data/gen/cards/NNN.json`. Если карточки не устраивают, поправить `prompts/card.md` (и при необходимости `prompts/card-examples.json`) и повторить `card-batches --pilot`.

### 3. Полный прогон

Повторять, пока `card-batches` создаёт пачки:

```bash
uv run --project content content card-batches --limit 8
# 8 субагентов card-writer параллельно, по одному на пачку
uv run --project content content validate
```

Агент пишет и исправляет черновик `NNN.draft.json` и переименовывает его в `NNN.json`, только когда закончит. Пока черновик не переименован, пачка считается ожидающей, поэтому `card-batches` можно запускать в любой момент, в том числе при скользящем окне: агент закончил → `card-batches --limit 1` → новый агент.

Если прогон прервался (например, кончилась квота), пачки без `NNN.json` остаются ожидающими, а их черновики не учитываются. Их нужно доделать до новых `card-batches`: `card-batches --limit N` ожидающие пачки не доделывает, а создаёт новые.

`assemble` можно запускать в любой момент: в `words.json` попадают только валидные карточки.

```bash
uv run --project content content assemble
```

Прогон закончен, когда `card-batches` печатает `0 new batches` и не печатает строку `waiting for output`. После этого нужно разобрать `stuck.md` и ещё раз запустить `validate` и `assemble`.

## Если что-то пошло не так

| Ситуация | Что делать |
|---|---|
| `card-batches` печатает `waiting for output (earlier batches): 005` | Субагент пачки 005 не дописал ответ. Запустить его на этой пачке ещё раз. Новые пачки с этими словами не создаются, пока старая ждёт ответа. |
| Ответ субагента — битый JSON | Все шаги останавливаются с ошибкой, в которой назван файл. Удалить этот `NNN.json`: пачка снова станет ожидающей, после чего перезапустить субагента. |
| Слово в `stuck.md` | Исправить карточку руками прямо в её последнем `NNN.json` и запустить `validate`. Другой вариант — перегенерировать через `card-batches --ids слово`. |
| Поменяли часть речи в `pos.json` после того, как карточка готова | Старая карточка останется валидной. Перегенерировать через `card-batches --ids слово`. |
| Добавили или убрали слова в `pos.json` | Уровни остальных слов сдвинутся при следующем `assemble`. Сами карточки от уровня не зависят. |
| `error: …pos.json is missing; run merge-pos first` | Шаг запущен до классификации или с неверным `--data`. |

## Устройство кода

| Модуль | Ответственность |
|---|---|
| `files.py` | `ContentError`, чтение JSON с понятными ошибками, атомарная запись |
| `paths.py` | все пути пайплайна от каталога данных |
| `ngsl.py` | чтение `NGSL_12_stats.csv` |
| `dictionary.py` | `POS`, `LEVELS`, `DictWord`, уровни, загрузка словаря из `pos.json` |
| `forms.py` | `lemma_forms`: кандидаты в формы-леммы |
| `classify.py` | шаги 1 и 3 |
| `rules.py` | `validate_card`: правила `data/README.md`, единственный источник правил |
| `store.py` | файлы пачек: номера, ожидающие, версии |
| `validate.py` | шаг 6 |
| `batches.py` | шаг 4 |
| `assemble.py` | шаг 7 |
| `cli.py` | аргументы, вывод, коды выхода |

Промпты лежат в `prompts/`: `classify.md`, `card.md` и `card-examples.json` с тремя образцовыми карточками (`house`, `find`, `between`).

Правила карточки проверяются в двух местах: в `rules.py` и в `web/src/lib/content/words.test.ts`. Для генерации главный — `rules.py`. При изменении правила нужно поправить оба места и `data/README.md`.

## Тесты

```bash
cd content && uv run pytest
```

- `test_prompt_examples.py` проверяет, что образцовые карточки из промпта проходят валидатор на настоящем списке NGSL.
- `test_ngsl.py::test_repository_csv_is_fixed` читает настоящий `data/wordlists/NGSL_12_stats.csv`, поэтому ему нужен локальный `data/`.
